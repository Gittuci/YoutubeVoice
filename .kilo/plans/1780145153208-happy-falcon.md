# Fix: Inline video bytes for Gemini Vision + skip File API upload

## Problem
`pipeline/eyes.py` uses `client.files.upload()` which is Gemini Developer API only — not available on Vertex AI. This is also wasteful: the video gets downloaded by yt-dlp, then re-uploaded to Google's servers (same ecosystem, same account owner).

## Root Cause
`genai.Client(vertexai=True)` rejects `client.files.upload()`. Vertex AI requires passing video as inline bytes or via Cloud Storage URI.

## Fix
Replace the file upload step in `eyes.py:analyze_video()` with inline bytes using `types.Part.from_bytes()`:

- Read video file to bytes
- Pass as `types.Part.from_bytes(data=video_data, mime_type="video/mp4")`
- Send directly in the `contents` list to `client.models.generate_content()`

No new API keys, no Gemini Developer API dependency, no env var changes.

### Files to change

1. **`pipeline/eyes.py`** — `analyze_video()` function (lines 33-74)
   - Remove: `client.files.upload()`, polling loop for ACTIVE state, File API usage
   - Add: `types.Part.from_bytes(data=video_data, mime_type="video/mp4")` passed inline
   
2. **`run_pipeline.py:20-22`** — `run_phase2()` 
   - Keep using `config.create_vertex_client()` (already correct)

### Why download is still needed
Phase 5 (fcpxml.py) needs the video file locally to extract dimensions, frame rate, and duration via ffprobe. The download is unavoidable for FCPXML generation.

### Why YouTube URL can't be passed directly
Vertex AI's `types.Part.from_uri()` requires `gs://` Cloud Storage URIs, not YouTube URLs. Direct YouTube access is a Gemini Developer API (AI Studio) feature only.
