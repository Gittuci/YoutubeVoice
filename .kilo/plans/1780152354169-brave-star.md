## Problem

**401 UNAUTHENTICATED** — Vertex AI's `GenerateContent` API rejects API keys entirely. The current `create_vertex_client()` passes `api_key=vertex_api_key`, but `vertexai=True` routes to Vertex endpoints which require OAuth2 credentials (ADC / service account), not API keys.

The API key in `.env` (`AIzaSyB...`) is a **Gemini Developer API key** — valid only for `vertexai=False` (AI Studio). Inline video bytes (`types.Part.from_bytes()`) work on both backends, but the auth path must match.

## Discovery

- **gcloud is installed** and has ADC at `C:\Users\user\AppData\Roaming\gcloud\application_default_credentials.json`
- **`admin@foltvilag.com`** is logged in (type: `authorized_user`, not service account)
- ADC quota project is `foltvilag-letolto-491615`, gcloud CLI project is `foltvilag-app-2026`, **config sets `foltvilag-enterprise-audio`** — three different projects
- **Phase 4 (TTS) requires Vertex AI** — `gemini-3.1-flash-tts-preview` is a Vertex AI-exclusive model, so we cannot switch entirely to Gemini Developer API

## Plan

### Single change: `pipeline/config.py` — `create_vertex_client()`

Remove `api_key=vertex_api_key` (Vertex AI rejects API keys). Add `project` and `location` (required when no API key to infer from). The SDK auto-detects ADC.

```diff
 def create_vertex_client() -> genai.Client:
     return genai.Client(
         vertexai=True,
-        api_key=vertex_api_key,
+        project=VERTEX_PROJECT,
+        location=VERTEX_LOCATION,
     )
```

`VERTEX_PROJECT = "foltvilag-enterprise-audio"` stays unchanged — confirmed as the project with Vertex AI enabled.

### ADC note

The SDK will look for ADC at the default path (`%APPDATA%\gcloud\application_default_credentials.json`). If the current ADC principal lacks permissions on `foltvilag-enterprise-audio`, the user may need:

```
gcloud auth application-default login --project=foltvilag-enterprise-audio
```

or set `GOOGLE_APPLICATION_CREDENTIALS` to a service account key JSON for that project.
