# Plan: Only speed up audio, never slow down

## Change

In `pipeline/voice.py`, modify the time-stretch logic in `generate_voiceover()` (lines 229-236) so that:

- **Audio longer than window:** speed up to fit (current behavior, keep it)
- **Audio shorter than window:** leave at normal speed, no slow-down stretching

Also report actual resulting duration in the segment tuple instead of always using `window_duration`.

## Code change in `voice.py:229-236`

**Before:**
```python
        # Stretch or compress to exactly fill the window
        if abs(actual_duration - window_duration) > 0.01:
            speed = actual_duration / window_duration
            safe_print(f"      Stretching: {speed:.2f}x -> {window_duration:.2f}s")
            pcm = _time_stretch_pcm(pcm, speed, sample_rate, ffmpeg_path)

        pcm_to_wav(pcm, wav_path, rate=sample_rate, channels=config.CHANNELS)
        segments.append((wav_path, start_s, window_duration))
```

**After:**
```python
        # Only speed up to fit the window; never slow down
        if actual_duration > window_duration + 0.01:
            speed = actual_duration / window_duration
            safe_print(f"      Speeding up: {speed:.2f}x -> {window_duration:.2f}s")
            pcm = _time_stretch_pcm(pcm, speed, sample_rate, ffmpeg_path)
            actual_duration = window_duration

        pcm_to_wav(pcm, wav_path, rate=sample_rate, channels=config.CHANNELS)
        segments.append((wav_path, start_s, actual_duration))
```

## Code change in `fcpxml.py:174`

Each WAV clip must start at the SRT subtitle start time. Currently a spurious `idx * 1.0 / timebase` frame offset accumulates per clip, shifting later clips away from their intended timeline position.

**Before:**
```python
        offset_s = start_s + (idx * 1.0 / timebase)
```

**After:**
```python
        offset_s = start_s
```
