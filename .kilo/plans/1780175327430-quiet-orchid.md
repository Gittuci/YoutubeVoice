# Plan: Streamlit Web UI for Interactive Pipeline Control

## Goal

Add a Streamlit web UI that lets you interactively browse files, configure settings, and run pipeline phases — while keeping the existing terminal CLI (`run_pipeline.py`) fully functional.

---

## Why Streamlit? (And What Are the Alternatives?)

You want two things: a graphical interface for convenience, and the terminal still working when you need me to fix or run things. Here are the realistic options and why Streamlit wins.

### The Contenders

| Tool | What it is | Good for | Weakness |
|------|-----------|----------|----------|
| **Streamlit** | Python library that turns scripts into web pages. You write normal Python and import `st`, it handles buttons, tables, file uploaders, progress bars. Opens in your browser on `localhost:8501`. | Data apps, dashboards, any Python project that needs a quick UI | Looks "web app" style, not a native desktop window |
| **Gradio** | Similar to Streamlit but optimized for ML model demos (image input/output, audio players). Also browser-based. | Audio preview, simple input→output flows | Harder to build multi-page dashboards with complex navigation |
| **NiceGUI** | Also browser-based, but lets you write UI code that looks more like a Vue/React app. More flexible layouts. | Custom designs, real-time updates | Steeper learning curve, more code to write |
| **Textual** | Terminal-based UI (TUI) that runs directly in PowerShell. No browser needed. Looks like a modern terminal app with panels, tables, keyboard shortcuts. | Keyboard-driven power users, no browser dependency | Can't show video thumbnails or audio players; mouse support is limited |
| **Tkinter** | Python's built-in GUI toolkit. Creates actual `.exe`-looking windows. No browser, no terminal tricks. | Native desktop feel, zero extra install | Looks old and clunky by default. A lot of manual work to make it look modern. No built-in audio player, no tables |
| **Electron / React / Vue** | Full web app frontend talking to a Python backend (FastAPI/Flask). | Professional custom UI, if you want to spend weeks on it | Massive overkill for this. You'd spend more time on CSS than on pipeline features |

### Why Streamlit Wins

1. **You already know Python** — Streamlit IS Python. A button is literally `if st.button("Download"):`. A table is `st.dataframe(data)`. You'd understand the code immediately because it's just your pipeline code wrapped in a few simple UI calls.

2. **Built-in widgets for exactly what you need** — file uploaders, YouTube URL input boxes, progress bars for long TTS runs, download buttons for FCPXML files, audio players for WAV previews. All one-liners.

3. **Lives alongside your existing code** — the `webui/` folder imports from `pipeline/` directly. `run_pipeline.py` stays exactly the same. You can still say "Kilo, run the pipeline for French" and I use the terminal. Or you open the web UI and click through phases yourself.

4. **Fastest to build** — I can write all 4 pages in about 30 lines of Streamlit code each. The heavy lifting is already done in your pipeline modules.

5. **Runs anywhere** — `streamlit run webui/app.py` opens `http://localhost:8501` in your browser. Close the tab, it stops. No installation, no build step.

### How It Feels to Use

Imagine this: you open your browser to `localhost:8501`. On the left sidebar you see what files exist in `output/`, which APIs are connected. In the center, a big field where you paste a YouTube URL followed by checkboxes for languages. You check "French" and "German", click **Run**. You see a progress bar as the video downloads, then as each TTS segment generates. When it's done, download buttons for the FCPXML files appear. Want to just regenerate the voiceover for one language? Click the **Voiceover** tab, pick the language, hit generate. No terminal commands to remember.

## Implementation

### 0. Architectural Requirements (User-Requested)

#### A. Strict Session State Management

Streamlit re-runs the entire script on every button click, checkbox, or tab switch. Without session state tracking, clicking a checkbox while Phase 4 is running would re-trigger the TTS generation from scratch.

**Solution — `st.session_state` dictionary as pipeline state machine:**

| Key | Type | Purpose |
|-----|------|---------|
| `video_path` | str or None | Path to downloaded video in `temp/` |
| `video_copy_path` | str or None | Path to copied video in `output/` |
| `srt_path` | str or None | Path to `master_hu.srt` |
| `translated_langs` | set | Language codes with existing `master_{lang}.srt` |
| `tts_complete` | dict[str→bool] | Languages with generated WAV segments |
| `fcpxml_generated` | dict[str→bool] | Languages with generated FCPXML |
| `is_running` | bool | True while any API process is active |
| `current_run` | str or None | Label of which operation is running ("Phase 2: Download", etc.) |
| `log_captured` | list | Accumulated log lines from the currently running phase |

**Guards on EVERY button:**

```python
if st.session_state.is_running:
    st.warning(f"A process is already running: {st.session_state.current_run}")
    st.stop()   # prevents the button logic from executing
```

**Buttons respect completed state:**

```python
if st.session_state.video_path:
    st.sidebar.success("Video downloaded")
    st.button("Download Video", disabled=True)
else:
    st.button("Download Video")
```

#### B. Visible Pipeline Logs

The pipeline modules use `safe_print()` (and sometimes raw `print()`) for all output. In the terminal this works great, but in Streamlit the user sees nothing unless they switch windows.

**Solution — `webui/log_capture.py` utility module:**

A single helper file with:
1. **`WebUILogCapture` class** — context manager that redirects `sys.stdout` to a `StringIO` buffer during a pipeline run
2. **`run_with_logs(func, *args, **kwargs) → (result, log_text)`** — convenience wrapper that runs any pipeline function, captures all print output, and returns both the result and the captured log

**Usage pattern in every page:**

```python
from webui.log_capture import run_with_logs

if st.button("Generate TTS"):
    st.session_state.is_running = True
    
    with st.status("Phase 4: TTS Voiceover Generation...", expanded=True) as status:
        result, log_text = run_with_logs(generate_voiceover, srt_path, lang, client, ffmpeg_path, wav_dir)
        st.text(log_text)
        status.update(label="Phase 4 complete!", state="complete")
    
    st.session_state.is_running = False
```

This means every `safe_print("      Raw: 3.38s (window: 1.70s)")` and `safe_print("      Speeding up: 1.99x -> 1.70s")` from `voice.py` appears in the browser inside a collapsible log panel — no tab switching needed.

### 1. Add `streamlit` to `requirements.txt`

One new dependency: `streamlit`. The `log_capture.py` utility uses only stdlib (`io`, `sys`, `contextlib`). No other new packages needed.

### 2. Create `webui/log_capture.py` — Shared Utility

A small module (no pipeline dependencies, stdlib only) that every page imports:

```python
# webui/log_capture.py
import io, sys, contextlib

class StdoutCapture:
    """Context manager that captures all stdout writes."""
    def __enter__(self):
        self.buffer = io.StringIO()
        self._old_stdout = sys.stdout
        sys.stdout = self.buffer
        return self.buffer
    def __exit__(self, *args):
        sys.stdout = self._old_stdout

def run_with_logs(func, *args, **kwargs):
    """Run a function, capture all print() output, return (result, log_text)."""
    with StdoutCapture() as buf:
        result = func(*args, **kwargs)
    return result, buf.getvalue()
```

### 3. Create `webui/app.py` — Main Dashboard Page

- **Session state initialization** (top of script): Initialize all keys (`is_running`, `video_path`, `srt_path`, etc.) to `None`/`False`/`{}` if they don't exist yet in `st.session_state`. This runs on every Streamlit re-run but only sets defaults on the first visit.

- **Sidebar:**
  - Project status overview (which files exist in `output/`) — uses `@st.cache_data(ttl=5)` to re-scan every 5 seconds
  - API key status indicator (Vertex AI, DeepSeek — green/red dots)
  - Language selector (checkboxes for hu/en/de/es/fr, stored in `st.session_state.selected_langs`)
  - Phase completion checkmarks (green/red based on session state keys)

- **Main area:**
  - Quick-start card: paste YouTube URL, pick languages, click "Run Full Pipeline"
  - Guard: if `st.session_state.is_running`, show spinner + current run label, disable "Run" button
  - Recent outputs table (browse generated FCPXML/WAV/SRT files)
  - Navigation: Streamlit auto-generates sidebar nav for pages/ folder

### 4. Create `webui/pages/1_Video.py` — Phase 2

- **Session state guard**: Button is disabled and shows "Already downloaded" if `st.session_state.video_path` is set
- YouTube URL input (stored in `st.session_state`)
- Download button → calls `run_with_logs(download_video, url, ...)` → displays captured log in `st.status()` → sets `st.session_state.video_path`
- Analyze button → calls `run_with_logs(analyze_video, ...)` → captures full Gemini analysis log → saves SRT → sets `st.session_state.srt_path`
- Video info display (resolution, duration, frame rate from ffprobe)
- SRT preview in expandable section with table (index, timestamp, text)

### 5. Create `webui/pages/2_Subtitles.py` — Phase 3

- **Session state guard**: Cannot proceed if `st.session_state.srt_path` is None — shows "Complete Phase 2 first"
- Browse existing SRT files in `output/` (picker)
- Preview SRT content in a `st.dataframe()` table (index, timestamp, text)
- Language picker for translation targets (multi-select)
- Translate button → calls `run_with_logs(translate_language, ...)` for each selected language → sets `st.session_state.translated_langs`
- Validation results: entry count comparison, timestamp integrity — shown as success/warning/error banners

### 6. Create `webui/pages/3_Voiceover.py` — Phase 4

- **Session state guard**: Button disabled if no SRT exists for the selected language OR `st.session_state.is_running`
- Language selector (dropdown, shows only languages with existing SRTs)
- Segment list table: index, SRT text, window duration, WAV status (exists/not generated)
- Per-segment audio preview (play button via `st.audio(wav_path)`)
- Run TTS button → within `st.status(expanded=True)`, calls `run_with_logs(generate_voiceover, ...)` → real-time log lines visible in the box → sets `st.session_state.tts_complete[lang]`
- Speed adjustment stats: table showing which segments were sped up and by how much (parse from captured log)
- Post-TTS: download links for individual WAVs, "Re-generate" option

### 7. Create `webui/pages/4_FCPXML.py` — Phase 5

- **Session state guard**: Button only enabled if `st.session_state.tts_complete[lang]` is True
- Language selector
- Generate button → calls `run_with_logs(build_fcpxml, ...)` → sets `st.session_state.fcpxml_generated[lang]`
- Download button for the `.fcpxml` file (`st.download_button`)
- Import instructions for DaVinci Resolve
- Timeline preview: clips as horizontal bars at SRT offsets (using Streamlit's `st.markdown` with colored divs)

### 8. Streamlit cache pattern

Use `@st.cache_resource` for API client creation (one-time init). Use `@st.cache_data` with TTL for file listings and SRT parsing so the UI stays snappy.

### 9. Keep CLI intact

No changes to `run_pipeline.py`, `pipeline/*.py`, or any existing code. The web UI is purely additive.
