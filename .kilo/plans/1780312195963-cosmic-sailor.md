### Section 6: DOs and DON'Ts
This is the critical section the user requested.

**DO:**
1. Run `python poc_tts.py` first to verify API keys and ffmpeg work
2. Check the sidebar API status dots (green = OK) before running phases
3. Complete phases in order (Phase 2 → 3 → 4 → 5)
4. Wait for each operation to fully complete before starting the next
5. Use the "Reset Session" button if something gets stuck
6. Use parallel TTS mode when generating many segments (faster)
7. Keep the terminal window open (don't close it during operations)
8. Save FCPXML files immediately after generation (download button)

**DON'T:**
1. **DON'T refresh the browser page during an active operation** — The pipeline continues running in the background but you LOSE the visual progress bar, status indicators, and log output. The `is_running` guard prevents restarting, but you can no longer see what's happening.
2. **DON'T open two browser tabs** — Streamlit creates separate sessions per tab. The `is_running` guard in the second tab won't know about the running operation in the first tab, potentially allowing duplicate TTS/API calls.
3. **DON'T close the terminal** — This kills the Streamlit server and any running background threads.
4. **DON'T delete output files manually mid-pipeline** — Subsequent phases depend on files from previous phases. Deleting `output/master_hu.srt` breaks Phase 3, deleting WAVs breaks Phase 5.
5. **DON'T run CLI and Web UI simultaneously** — Both write to the same `output/` directory. Concurrent operations cause file conflicts and corrupted results.
6. **DON'T skip Phase 2** — The video and master SRT are required by all other phases.
7. **DON'T ignore rate limit errors** — If you see "RESOURCE_EXHAUSTED" or 429 errors, wait a few minutes before retrying. Parallel mode with high worker counts can trigger rate limits.
