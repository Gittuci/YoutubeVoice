# Plan: Audio Transcription with Tone/Intonation Analysis

## Goal
Add a new optional pipeline phase that transcribes audio speech from videos or standalone audio files, capturing tone, intonation, emphasis, and emotion markers. These markers flow through translation into TTS generation, making multi-language voiceovers match the original speaker's delivery.

## Design Summary
- **New module**: `pipeline/ears.py` — Phase 1.5: Audio → SRT with tone tags
- **Tone representation**: Inline expression tags in SRT text (e.g., `[enthusiastic]`, `[slow]`, `[calm]`) — same tag system already used by `_build_tagged_text()` and `expression_tags.txt`
- **API**: Gemini Audio API (Vertex AI) as primary, with a pluggable `Transcriber` abstraction for future Whisper/ElevenLabs support
- **Pipeline flow**: Phase 1.5 optionally runs between Phase 1 (PoC) and Phase 2 (Vision), enriching or replacing the visual-only SRT
- **Backward compatible**: Default path unchanged — transcription only runs when user opts in

## Detailed Design

### 1. New Module: `pipeline/ears.py`

Contains:
- `Transcriber` abstract base class with `transcribe(audio_path: str) -> str` method
- `GeminiAudioTranscriber(Transcriber)` — sends audio to Gemini Audio API with a prompt requesting SRT format with tone/emotion tags inline
- `extract_audio(video_path: str, output_path: str, ffmpeg_path: str) -> str` — extract audio track from video as 16kHz mono WAV using ffmpeg
- `main()` — CLI entry point: `python -m pipeline.ears --input video.mp4 --output output`

#### GeminiAudioTranscriber Details
- Uses `client.models.generate_content()` with `response_modalities=["TEXT"]`
- Sends audio bytes as `types.Part.from_bytes(data=audio_bytes, mime_type="audio/wav")`
- Prompt instructs Gemini to:
  1. Transcribe speech to text in SRT format with timestamps
  2. Tag each segment with emotion/tone markers: `[enthusiastic]`, `[calm]`, `[urgent]`, `[explanatory]`, `[slow]`, `[emphatic]`, `[questioning]`, `[warm]`, `[matter-of-fact]`
  3. Output ONLY valid SRT with inline tags (no markdown, no commentary)

#### Pluggable Transcriber System
```
pipeline/ears.py
├── Transcriber (ABC) — abstract interface
│   └── transcribe(audio_path: str, language: str) -> str
├── GeminiAudioTranscriber(Transcriber)
│   └── uses gemini-2.5-flash with audio modality
├── WhisperTranscriber(Transcriber) — future, via OpenAI API
├── ElevenLabsTranscriber(Transcriber) — future
└── get_transcriber(name: str = "gemini") -> Transcriber
```

Config additions in `pipeline/config.py`:
```python
AUDIO_TRANSCRIBER = "gemini"  # "gemini", "whisper", "elevenlabs"
GEMINI_AUDIO_MODEL = "gemini-2.5-flash"  # same as vision, supports audio
```

### 2. Tone Tag System

Current tag: single `[enthusiasm]` hardcoded for first segment only.

New tag vocabulary (defined in `prompts/expression_tags.txt`):
```
[enthusiastic] [calm] [urgent] [explanatory] [slow] 
[emphatic] [questioning] [warm] [matter-of-fact] [excited]
[gentle] [serious] [encouraging] [step-by-step]
```

#### Tag Flow Through Pipeline
```
Phase 1.5: Audio → SRT with inline tags
    "1\n00:00:01,000 --> 00:00:04,000\n[warm] Welcome to today's tutorial.\n\n"
    "2\n00:00:04,000 --> 00:00:07,000\n[enthusiastic] Today I'll show you an amazing technique.\n\n"

Phase 3: Translation preserves tags
    "1\n00:00:01,000 --> 00:00:04,000\n[warm] Willkommen zum heutigen Tutorial.\n\n"

Phase 4: TTS reads tags per segment
    _build_tagged_text() now uses the tag from SRT text instead of hardcoded is_first
```

#### Required change to `_build_tagged_text()`
```python
# Before: only tags first segment with [enthusiasm]
def _build_tagged_text(entry_text: str, is_first: bool) -> str:
    tag = config.load_prompt("expression_tags.txt")
    tagged = entry_text
    if is_first:
        tagged = f"{tag} {tagged}"
    return tagged

# After: reads tag already in the text, applies it
def _build_tagged_text(entry_text: str) -> str:
    return entry_text  # tags are already embedded in the SRT text
```

The tag is already in the SRT text — no need to re-inject. The TTS prompt (`tts_generation.txt`) already passes `{text}` directly, so tags flow through naturally.

#### Required change to `_process_one_segment()` and callers
Remove the `is_first` parameter and `_build_tagged_text()` call, since tags are now in the SRT text directly.

### 3. SRT Processing Changes

#### `pipeline/brains.py` — Translation
The translation prompt (`translate_system.txt`) must be updated to instruct the model to:
- **Preserve** inline tone tags (e.g., `[enthusiastic]`) unchanged
- Only translate the actual text content

Updated `translate_system.txt`:
```
Translate the following {source_lang} SRT subtitles into {target_lang}.
STRICT RULES:
- Preserve ALL SRT entry indexes and timestamps EXACTLY.
- Preserve ALL inline tone markers like [enthusiastic], [calm], etc. — keep them unchanged.
- Only translate the actual text content (words after the tone marker, if present).
- Keep translations natural, instructional, and concise.
- Output valid SRT format only — no commentary, no markdown.
- Start your response with the first SRT index number.
```

#### `pipeline/utils.py` — Updated `parse_srt()`
The SRT parser already returns `entry["text"]` including tags — no change needed since tags are just part of the text line.

### 4. TTS Integration

#### `pipeline/voice.py` — Simplified `_build_tagged_text()`
Since tags are in the SRT text, `_build_tagged_text()` becomes a pass-through:
```python
def _build_tagged_text(entry_text: str) -> str:
    return entry_text
```

#### `_process_one_segment()` signature change
Remove the `is_first` parameter (no longer needed since we don't conditionally prepend a tag).

#### Callers to update:
- `generate_voiceover()` — remove `i == 0` argument
- `generate_voiceover_parallel()` — remove `is_first` in `process_segment()`

### 5. Pipeline Orchestration

```

```

#### `pipeline/ears.py` CLI
```

```

Components:

## Design Decisions

**Why inline tags instead of sidecar JSON?**
- Already supported by the existing expression tag system
- Survives translation (tags are language-agnostic)
- No new file format to manage, sync, or lose
- Works with existing SRT validation and parsing

**Why new phase instead of extending Phase 2?**
- Transcription and vision analysis are independent operations
- Either can succeed while the other fails
- User should control whether to use audio (mute videos skip it)
- Clean separation of concerns

**Why pluggable transcriber?**
- User wants to try different models (Whisper, ElevenLabs)
- Different cost/accuracy tradeoffs
- Gemini (Vertex AI) is free with existing key — good default
- Abstraction makes it easy to add new providers later

## Risks / Open Questions

- **Mute videos**: If video has no audio, transcription produces empty/garbage SRT. Need a guard — check audio duration/silence before transcribing, fall back to vision-only.
- **Tag hallucination**: Gemini might invent tone tags for silent segments or mislabel emotions. The prompt should be explicit about only tagging when confident.
- **Translation tag loss**: DeepSeek might strip tone tags during translation. The updated prompt helps, but validation may need to check tag preservation.
- **Cost**: Gemini Audio transcription costs tokens for audio input (~$0.02–0.10 per 5-min audio), similar to vision analysis. Total pipeline cost doubles if both vision and audio run.
