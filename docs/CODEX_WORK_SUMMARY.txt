======================================================================
2. INHERITED PROJECT STATE FROM KILO.AI
======================================================================

The inherited project contains these primary components:

- run_pipeline.py
  Orchestrates video analysis/transcription, translation, TTS, and FCPXML.

- pipeline/eyes.py
  Sends inline video bytes to Vertex Gemini and asks directly for Hungarian SRT.

- pipeline/ears.py
  Extracts source audio and asks Gemini for SRT with tone tags.

- pipeline/brains.py
  Uses DeepSeek first and Gemini as fallback for translation.

- pipeline/voice.py
  Generates one Gemini TTS WAV per subtitle entry and accelerates audio with
  FFmpeg atempo whenever an utterance is longer than its SRT window.

- pipeline/fcpxml.py
  Generates FCPXML 1.12 with muted source video and positioned WAV clips.

- webui/
  Streamlit interface with incomplete/broken functionality.

Important inherited limitations:

- SRT is treated as the canonical internal state, even though it cannot preserve
  evidence, uncertainty, teaching intent, terminology, or flexible timing.
- The video-analysis prompt is hardcoded for one EPP hexagon demonstration.
- German, Spanish, and French translation use English as a pivot rather than
  localizing directly from Hungarian/source meaning.
- TTS segments can be accelerated aggressively and silently to fit fixed SRT
  windows.
- Raw TTS duration and applied speed are not persisted.
- WAV cache validity is based mainly on modification time rather than content and
  configuration hashes.
- Audio transcription validation is weaker than video/SRT validation.
- Resume state relies too heavily on Streamlit session state.
- The UI has an undefined wav_dir reference, an unfinished full-pipeline action,
  and missing Streamlit in the original virtual environment.
- There is no automated test suite, dependency lock file, or pyproject.toml.
- The existing application configuration hardcodes older model names and a
  us-central1 Vertex location.
- The CLI/UI incorrectly treats VERTEX_API_KEY presence as a prerequisite even
  though Vertex actually authenticates with service-account ADC.

These issues remain open. Codex deliberately did not modify production code
before validating the desired workflow and providers.

13. RECOMMENDED ARCHITECTURE
======================================================================

SRT should not be the source of truth.

Recommended canonical state:
  a structured, versioned project document containing semantic units.

Each unit should retain:

- source meaning and evidence;
- visible actions, tools, materials, components, and timestamps;
- teaching intent;
- importance: required/useful/optional;
- terminology and pronunciation hints;
- tone, emphasis, rhythm, and speaker identity;
- hard and soft timing bounds;
- safe placement flexibility;
- localized scripts;
- provider/model/voice configuration;
- input hashes;
- raw/final audio durations;
- placement and speed adjustments;
- confidence, uncertainty, and human-review state.

Recommended flow:

1. Ingest and probe media.
2. Determine whether useful source speech exists.
3. Build independent speech and visual timelines when applicable.
4. Fuse evidence into semantic instructional units.
5. Review and lock meaning and terminology.
6. Localize directly into each target language.
7. Plan narration windows and fit text before TTS.
8. Generate/audition coherent speech groups.
9. Place, mix, normalize, and validate audio.
10. Derive SRT and FCPXML as exports.

Mute-video policy:

- First pass: factual visual timeline with evidence/confidence.
- Second pass: instructional commentary based on the approved timeline.
- Do not force one model call to understand the technique and immediately emit
  final SRT.

Speech-containing-video policy:

- Hungarian speech is the primary semantic source.
- Vision supplies complementary evidence.
- Visual evidence may disambiguate “this,” “here,” or “the other side.”
- Corrections and additions must be reviewable and traceable.
- Support faithful dubbing and enhanced instructional localization as separate
  modes.


======================================================================
14. NATURAL-SPEECH TIMING POLICY
======================================================================

Priority order:

1. Natural speech quality
2. Correct instructional meaning
3. Professional terminology
4. Natural target-language phrasing
5. Timing fit

If narration is too long:

1. Remove nonessential wording.
2. Rewrite more concisely and idiomatically.
3. Improve segmentation or merge adjacent units.
4. Shift placement within safe visual bounds.
5. Redistribute narration across nearby silence or ongoing work.
6. Regenerate TTS.
7. Only then consider a small pitch-preserving speed adjustment.

Suggested limits:

- Approximately 1.03x may be acceptable by default.
- Above 1.05x requires explicit warning and review.
- Never silently exceed the configured ceiling.

Always preserve:

- raw audio;
- raw duration;
- final audio;
- final duration;
- applied speed;
- source text revision;
- placement;
- provider/model/voice configuration.
